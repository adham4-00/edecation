On initialization, the front and the size of the array is set to 0, as there are no elements in the list, and the front will remain 0 until the dequeue() method is called. 
When a user uses the enqueue() method, the code mainly does two things. 1. It increases the size of the list by one, then 2: adds the element in the earliest empty slot and 
Not the last slot. Using the following formula, it gets the index of the first element in the list, then adds it to the size of the list to get the index that is the earliest. 
In the list, for example, the first element to be added to the list would have an index and a size of 0 (as initialized), so the earliest empty slot would be 0, and it would add 1 to the size. 
So the next empty index will be 1 and so on.
Now the tricky part: what if we reach the list's last index? Do we use the resize() method? But what if there was an empty slot in the back? Could that be possible? of course

and the front's index is also now 1 (I will touch on that in the dequeue() ), you get the following equation: (1+1)%2 = 0; there's nothing left, so the answer is 0, which is the empty slot's index! 
We are done with the most convoluted method, but we still have two more to go
So what if the entire list is full? All the slots have a value, but the user wants more? 
Here comes the resize method. Each time the enqueue() is used, the code checks if the list is full, and if it is, it uses the resize() method with a parameter of 2*the size of the list.
What that method does is create a new list with the aforementioned size and transfer the content of the old list to it with a for loop while also using the
